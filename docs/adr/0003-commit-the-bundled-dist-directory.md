# Commit the bundled dist/ directory

GitHub runs a JavaScript action by executing a file straight from the repository, with no install or build step of its own, so whatever the action needs at runtime must already be committed. We bundle the entire source and all dependencies into a single committed file rather than committing `node_modules` or moving to a container-based action.

## Consequences

Generated output is tracked in git, so `dist/` appears in diffs and must never be hand-edited — it is regenerated by the `pre-push` hook and committed by contributors alongside the source change, and re-committed by semantic-release as part of a release. A source change that is not accompanied by a rebuild ships nothing, which makes "build runs as part of validation" a correctness requirement rather than a convenience.

A container-based action would have avoided the committed bundle, at the cost of pulling or building an image on every Run — far slower for an action whose actual work takes seconds.
