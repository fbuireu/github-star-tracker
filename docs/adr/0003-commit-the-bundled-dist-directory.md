# 3. Commit the bundled dist/ directory

Date: 2026-07-26

## Status

Accepted.

## Context

GitHub runs a JavaScript action by executing a file straight from the repository, with no install or build step of its own, so whatever the action needs at runtime must already be committed. Committing `node_modules` wholesale would satisfy that and nothing else. A container-based action would have avoided the committed bundle entirely, at the cost of pulling or building an image on every Run — far slower for an action whose actual work takes seconds.

## Decision

The entire source and all dependencies are bundled into a single committed file under `dist/`.

## Consequences

- Generated output is tracked in git, so `dist/` appears in diffs and must never be hand-edited — it is regenerated by the `pre-push` hook and committed by contributors alongside the source change, and re-committed by semantic-release as part of a release.
- A source change that is not accompanied by a rebuild ships nothing, which makes "build runs as part of validation" a correctness requirement rather than a convenience.
